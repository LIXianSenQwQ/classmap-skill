# Classmap Skill

中文 | [English](README.en.md)

**减少重复探索，帮助 AI 编程助手区分代码职责。**

Classmap Skill 用一张轻量的 `CLASSMAP.md`，保存已经核实的业务入口、代码位置和职责边界。下一次会话或换一个编程助手时，可以从这些线索继续查证，复用之前的探索结果。

免费开源，使用 Markdown 维护，配合智能体已有的代码搜索与阅读能力工作。

## 为什么需要它

维护已有项目时，一些问题会在不同任务里反复出现：

- **同一个模块反复摸索**：上次已经查清登录流程，下次新会话又从目录和关键词开始找。
- **搜到文件，仍分不清职责**：登录校验、令牌续期和页面跳转分散在不同模块，名称或关键词相近。
- **业务说法与代码命名不同**：用户说“登录过期后回到原页面”，代码却分布在会话管理、请求拦截器和路由守卫中。

Classmap Skill 把值得复用的发现记成“功能或变更线索 → 代码位置 → 职责与边界”。后续任务据此选择阅读起点，再核实当前代码。

它的价值在于保留项目知识、减少重复摸索。

## 如何复用探索结果

### 两个 skill，一张地图

| Skill | 职责 |
|---|---|
| `classmap-maintain` | 把已核实的主要入口与职责整理成地图，按要求创建、更新或检查。 |
| `classmap-target` | 复用地图中的线索，读取当前代码，确认本次需求涉及哪些职责；要求实现时继续修改。 |

### 一张小表，记住值得复用的职责

下面是一个示意地图；实际条目必须来自项目中已核实的代码：

```md
# CLASSMAP.md

用于筛选候选文件，查图后仍需核实当前代码。覆盖主要行为，不逐个收录所有文件。

| 功能 / 变更线索 | 主要代码 | 职责与边界 |
|---|---|---|
| 登录校验、失败限制 | `src/auth/LoginService.ts` | 组织登录校验流程；令牌签发由 TokenService 负责。 |
| 令牌签发、刷新 | `src/auth/TokenService.ts` | 管理令牌生成与刷新规则。 |
```

优先记录常用业务入口、容易混淆的职责和关键模块交接点。路径相对于仓库根目录，必要时补充符号名。保留有用的手工备注，避免把地图变成逐文件清单。

### 从已知线索开始，用当前代码确认

通常先查地图，再读取候选代码。用户已给出明确文件或符号时，可直接从该位置开始，按需查地图。

验证后的输出可以很短，例如：

```md
- 优先查看 `src/auth/LoginService.ts`：登录流程在这里组织凭据校验和失败限制。
- 如果请求或响应字段需要变化，再查看 `src/auth/AuthController.ts`：它负责 HTTP 契约。
```

这个例子区分了“登录规则”和“HTTP 契约”：后续任务可以按变更内容选择起点。输出只保留有用的职责、相关文件和未确认事项；定位到职责文件并不代表已证明故障根因。

地图遗漏不代表代码不存在。候选代码不足以解释行为时，沿入口和调用关系查找，再按需扩展到模块搜索或全仓定向搜索；没有明确模块时可以直接定向搜索。地图缺失时仍完成当前定位，不顺便创建地图。

### 明确读写边界，按需增量维护

| 用户要求 | 行为 |
|---|---|
| 仅定位、解释、分析、审查或检查地图是否过期 | 只读，报告定位依据、未确认事项和地图偏差。 |
| 实现或修复功能 | 完成请求；定位事实变化时局部同步已有地图。 |
| 创建、刷新或修复地图 | 使用 `classmap-maintain`，在指定范围内维护。 |

实现任务中，只有职责、路径或入口等事实变化会影响后续定位时，才局部同步已有地图；职责不变的内部修复无需更新。只维护本次任务中核实的相关条目，建图和全面刷新不阻塞当前任务。

## 与智能体已有能力配合

| 方式 | Classmap Skill 的作用 |
|---|---|
| 智能体搜索与代码阅读 | 地图提供已核实的历史线索；智能体继续阅读当前实现、跟踪调用并处理歧义。 |
| README / CODEMAP / 目录结构 | 补充业务行为对应的代码职责，优先记录容易混淆的边界。 |
| 符号索引 / 依赖图谱 | 配合使用：符号与调用关系帮助追踪实现，职责说明帮助判断应从哪里开始。 |

`CLASSMAP.md` 只保存职责和定位线索。业务术语、架构决策和任务计划沿用项目现有文档。地图可能遗漏或过期，当前代码优先；需要完整依赖查询或严格影响分析时，应使用相应工具。

## 快速使用

### 安装

推荐通过 npm 使用 `npx` 一键安装：

```bash
npx @qingyuwanan/classmap-skill install
```

默认会把两个 skill 安装到 `~/.agents/skills`：

- `~/.agents/skills/classmap-maintain`
- `~/.agents/skills/classmap-target`

如果这两个目录已经存在，安装器会直接覆盖同名目录。它只会处理这两个固定目录，不会删除或改动 `~/.agents/skills` 下的其他 skill。

如果需要安装到其他 skills 目录，可以指定 `--target`：

```bash
npx @qingyuwanan/classmap-skill install --target ~/.codex/skills
```

### 使用

#### 1. 创建或刷新地图

在一个已有项目里运行：

```txt
/classmap-maintain
```

未附加要求时，默认创建或刷新 `CLASSMAP.md`。也可以指定只维护某个模块。

#### 2. 只定位，不修改

```txt
/classmap-target 我要给登录增加邮箱验证码，只帮我定位应该改哪些代码，暂不修改。
```

预期流程：

```txt
读取地图或从明确文件开始
-> 读取候选代码，必要时定向搜索
-> 输出已验证的职责、位置和剩余不确定性
-> 结束，不修改代码或地图
```

#### 3. 定位并实现

```txt
/classmap-target 给登录增加邮箱验证码，请先定位相关代码，再完成实现。
```

验证定位后继续实现；只有影响后续定位时，才同步已有地图中的相关条目。地图缺失时不会自动创建。

#### 4. 检查或修复过期信息

仅检查，不写文件：

```txt
/classmap-maintain 检查登录模块的 CLASSMAP.md 条目是否过期，只报告。
```

明确要求修复：

```txt
/classmap-maintain 核实并更新登录模块的过期条目，保留其他模块内容。
```

## 适合谁

- 经常用 AI 维护同一项目，希望跨会话复用探索结果的人。
- 项目有多个模块、相似名称或新旧实现，需要区分职责的团队。
- 愿意用 Markdown 维护少量关键入口与边界的项目。

只有几个文件的小 demo 通常无需单独建图。需要完整依赖查询、严格影响分析或全自动零维护索引的场景，也超出本项目的定位。

实际收益取决于项目复杂度、地图质量和复用频率；目前没有量化的提速或准确率对照数据。
