# Classmap Skill

中文 | [English](README.en.md)

## 一句话介绍

Classmap Skill 用一张 `CLASSMAP.md` 帮助 AI 编程助手定位代码职责：某个行为由谁负责、应该先看哪个文件，以及容易混淆的职责边界。

地图记录“功能或变更线索 → 代码位置 → 职责”，先筛选候选，再核实当前代码并给出定位结论。只有用户要求实现时，才继续修改代码。

## 解决问题

用户通常知道要改什么，却不一定知道行为在哪个文件中：

- “改登录逻辑”“加支付回调”“修订单状态 bug”需要先找到负责的代码。
- 名称相近的类、组件或模块可能承担不同职责，关键词命中后仍需判断。
- 代码移动或职责转移后，旧文档可能把下一次任务带到错误位置。

Classmap Skill 提供可人工维护的轻量职责索引，帮助缩小阅读范围。

## 功能特点

### 两个 skill，一张地图

| Skill | 职责 |
|---|---|
| `classmap-maintain` | 按要求创建、刷新或检查地图；仅检查时只读，不实现业务功能。 |
| `classmap-target` | 根据需求筛选候选代码，读取验证后给出定位结论；用户要求实现时继续，并按需局部同步已有地图。 |

### 默认只保留三类信息

下面是一个示意地图；实际条目必须来自项目中已核实的代码：

```md
# CLASSMAP.md

用于筛选候选文件，查图后仍需核实当前代码。覆盖主要行为，不逐个收录所有文件。

| 功能 / 变更线索 | 主要代码 | 职责与边界 |
|---|---|---|
| 登录校验、失败限制 | `src/auth/LoginService.ts` | 组织登录校验流程；令牌签发由 TokenService 负责。 |
| 令牌签发、刷新 | `src/auth/TokenService.ts` | 管理令牌生成与刷新规则。 |
```

路径相对于仓库根目录；同一文件包含多种职责时，可补充符号名。边界只在容易混淆时说明，调用者、依赖和测试只在帮助定位时记录，无需额外的固定字段。未确认的职责直接说明缺少的证据，不设置置信度评分。

优先收录常用业务入口、核心实现、容易混淆的职责和关键模块交接点。普通 DTO、包装类、工具和测试不逐项收录。首次生成覆盖已识别的主要行为后即可结束，必要时说明尚未覆盖的区域。

已有地图的有效布局和有用手工备注会保留，不强制转换格式，也不重复生成一套逐文件详情。

### 先验证，再给出定位结论

通常先查地图，再读取候选代码。用户已给出明确文件或符号时，可直接从该位置开始，按需查地图。

验证后的输出可以很短，例如：

```md
- 优先查看 `src/auth/LoginService.ts`：登录流程在这里组织凭据校验和失败限制。
- 如果请求或响应字段需要变化，再查看 `src/auth/AuthController.ts`：它负责 HTTP 契约。
```

只在有帮助时补充相关文件或排除理由，不要求固定的主目标、次目标、排除项和搜索预算报告。已确认的职责与尚未核实的候选会区分说明；定位到职责文件并不代表已证明故障根因。

地图遗漏不代表代码不存在。候选代码不足以解释行为时，沿入口和调用关系查找，再按需扩展到模块搜索或全仓定向搜索；没有明确模块时可以直接定向搜索。地图缺失时仍完成当前定位，不顺便创建地图。

### 明确读写边界，按需增量维护

| 用户要求 | 行为 |
|---|---|
| 仅定位、解释、分析、审查或检查地图是否过期 | 只读，报告定位依据、未确认事项和地图偏差。 |
| 实现或修复功能 | 完成请求；定位事实变化时局部同步已有地图。 |
| 创建、刷新或修复地图 | 使用 `classmap-maintain`，在指定范围内维护。 |

已有地图只在这些变化会影响后续定位时更新：重要职责新增、转移或移除；文件移动、重命名或删除影响已有路径；主要入口改变；本次任务确认原定位信息有误。

新增普通工具或测试、替换内部依赖、修复职责不变的内部逻辑，都不单独触发更新。只更新当前任务中核实的相关条目，范围外的过期信息仅报告；建图和全面刷新不阻塞当前任务。

### 文档边界清晰

`CLASSMAP.md` 只保存职责和定位线索。业务术语、架构决策和任务计划分别沿用现有的领域文档（如 `CONTEXT.md`）、设计文档或 `docs/adr/`、任务文档；skill 不自动创建这些文档。

## 与其他方式配合

| 方式 | Classmap Skill 的作用 |
|---|---|
| README / CODEMAP / 目录结构 | 在已有项目说明之上，补充行为对应的代码职责和容易混淆的边界。 |
| 关键词搜索 | 用地图提供候选，再用代码读取和定向搜索核实或补充。 |
| 依赖图谱 / 影响分析系统 | 聚焦日常职责定位，不维护完整调用关系或提供完整影响分析。 |

## 快速使用

### 安装

推荐通过 npm 使用 `npx` 一键安装：

```bash
npx @qingyuwanan/classmap-skill install
```

默认会把两个 skill 安装到 `~/.agents/skills`：

- `~/.agents/skills/classmap-maintain`
- `~/.agents/skills/classmap-target`

如果这两个目录已经存在，安装器会直接覆盖同名目录。它只会处理这两个固定目录，不会删除或改动 `~/.agents/skills` 下的其他 skill。

如果需要安装到其他 skills 目录，可以指定 `--target`：

```bash
npx @qingyuwanan/classmap-skill install --target ~/.codex/skills
```

### 使用

#### 1. 创建或刷新地图

在一个已有项目里运行：

```txt
/classmap-maintain
```

未附加要求时，默认创建或刷新 `CLASSMAP.md`。也可以指定只维护某个模块。

#### 2. 只定位，不修改

```txt
/classmap-target 我要给登录增加邮箱验证码，只帮我定位应该改哪些代码，暂不修改。
```

预期流程：

```txt
读取地图或从明确文件开始
-> 读取候选代码，必要时定向搜索
-> 输出已验证的职责、位置和剩余不确定性
-> 结束，不修改代码或地图
```

#### 3. 定位并实现

```txt
/classmap-target 给登录增加邮箱验证码，请先定位相关代码，再完成实现。
```

验证定位后继续实现；只有影响后续定位时，才同步已有地图中的相关条目。地图缺失时不会自动创建。

#### 4. 检查或修复过期信息

仅检查，不写文件：

```txt
/classmap-maintain 检查登录模块的 CLASSMAP.md 条目是否过期，只报告。
```

明确要求修复：

```txt
/classmap-maintain 核实并更新登录模块的过期条目，保留其他模块内容。
```

## 适合谁

- 经常用 AI 修改已有项目，需要跨会话保留关键代码职责的人。
- 项目有多个模块或容易混淆的职责，希望减少定位噪声的团队。
- 希望用 Markdown 维护少量可靠入口，不需要完整代码索引的项目。

只有几个文件的小 demo 通常无需单独建图。需要完整依赖查询、严格影响分析或全自动零维护索引的场景，也超出本项目的定位。
